## 先恢复数据

```powershell
git clone https://github.com/junlongli482-del/wnsmw.git
cd wnsmw
python backup/restore_snapshot.py --download
```

需要安装 Python 3.12 x64 与 GitHub CLI（`gh`）；若新电脑的 gh 提示登录，先执行 `gh auth login`。公开附件也可以直接在浏览器里手动从 Release 下载，不依赖旧电脑的登录状态。分卷拼接顺序和哈希由 `snapshot-manifest.json` 定义；不要单独解压 `.001`，运行恢复脚本拼接。首次恢复按原路径结构覆盖同名研究文件，宜在新克隆的仓库执行。解压完成还会逐文件核验哈希。建议至少预留 25 GB 空闲空间，容纳下载分卷、拼接 ZIP 和解压后的研究文件。

附件分两组：研究状态包保留全部 `output/camscanner-reverse`、Ghidra 项目、原 APK/库/模型、壳内存与 emulation 检查点、Android 研究构建与夹具；环境包保留 Python 依赖、已校验 JADX JAR、Frida 组件与 REA 源码 bundle。未保存非扫描项目的教学平台文档。私人 keystore 排除，研究构建脚本会生成新的调试签名；重新构建的 APK 哈希因此可能不同。

## 快速恢复原库验证

1. 新建并启动 API30 x86 模拟器，使用端口 5580；ADB serial 对应 `emulator-5580`。旧模拟器磁盘未备份，不依赖旧 App 数据。
2. 安装 `output/camscanner-reverse/scanner-native-restored-research.apk`。
3. 修正启动脚本的 Node 路径后，在仓库根目录运行 `powershell -File scanner/start_native_gateway.ps1 -Port 18767`。脚本自动安装研究 APK、启动 HTTP 阶段，并将 Android 18765 转发至电脑。
4. 顺序执行下列验证。它们共享有状态原库服务，勿并行运行，也不要同时运行会 force-stop 或重新安装研究 APK 的其他脚本。

```powershell
python scanner/verify_curve_gateway.py --base http://127.0.0.1:18767
python scanner/verify_native_gateway.py --base http://127.0.0.1:18767
$env:SCANNER_TEST_BASE='http://127.0.0.1:18767'
node scanner/verify_wechat_page.mjs
```

`verify_curve_gateway.py` 使用 Pillow，可在 Python 3.12 安装 `pillow`。其它探针可能需要 Python 库，按导入错误补装；保留的 cp312 依赖不能用于 Python 3.13。

微信配置 `scanner/wechat-miniprogram/config.js`：`curveBorder: true` 开启 80 点曲线；`baseUrl` 要指向手机可访问的服务。手机 127.0.0.1 不是电脑，真实微信需要 HTTPS 合法域名及 AppID。当前成果是研究网关，微信 JS 无法直接载入 Android JNI。
