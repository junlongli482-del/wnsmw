# 超级滤镜：本地实现与服务端边界

## 结论

已经恢复出两套不同的增强路径，不能把它们统称为“超级滤镜本地模型”。

1. `enhanceMode == -12` 的全增强入口会编码临时 JPEG，并调用 `SuperFilterEngine.saveSuperFilterImage`；该方法检查网络后调用 `TianShuAPI.executeSuperFilter2`，保存响应图像。成功时将响应头 `X-IS-Filter-Version` 回写到同步记录。此路径的图像变换发生在服务端，现有 APK/本地证据没有恢复服务端模型或实现。
2. 设备支持且实验策略允许时，普通滤镜选择可走本地 `MagicEnhancer.ImageSilverBulletFile`。另有 `-10/-11` 去阴影分支：分别调用旧版/新版 `MagicEnhancer.deshadowFile*`。这几条本地路径是原始库代码，可实测复用；它们与 `-12` 云端超级滤镜不是同一个已证实路径。

## 原代码证据

- `restored-SuperFilterEngine.java.txt`：
  - `enhanceImageAllS` 对 `-12` 先把 image struct 编码为 JPEG，传入 `saveSuperFilterImage`；其他模式直接 `ScannerUtils.enhanceImageS(..., 1)`。
  - `saveSuperFilterImage` 在无网络时返回 `1`；在线时计算 MD5/文件大小、按配置压缩，传给 `TianShuAPI.executeSuperFilter2`；网络/服务失败返回 `3`，超时可返回 `5`，成功将响应流保存到输出路径并返回 `0`。
  - 响应头 `X-IS-Filter-Version` 可写入 `ImageFilterBackflowUtil`。
  - `isAllowLocalSuperFilter` 由 CPU 最大频率 `> 1,710,000` 且 `!SuperFilterStyleExp...` 决定。
- `restored-ScannerUtils.java.txt`：
  - `saveSuperFilterLocal` 直接调用 `MagicEnhancer.ImageSilverBulletFile(input, output, mode, fastFlag, cpuCount)`。
  - `enhanceImageFile` 的 `-12` 返回 `false`；`-10` 使用 `MagicEnhancer.deshadowFile`，`-11` 根据 `isUsingNewMagicDeShadow` 选择 `deshadowFile2` 或 `deshadowFileNew`，处理类型参数为 `3`。
  - `enhanceImageBySuperFilter` 明确设置 `imageEnhanceMode(-12)`，并交给 `ImageProgressClient.executeProgress`；这个入口的命名不能证明它走本地 `saveSuperFilterLocal`，实际 `-12` 分支由 `SuperFilterEngine` 证实为云端请求。
- `restored-MagicEnhancer.java.txt` 与 `restored-SessionIdPoolManager.java.txt`：旧/新去阴影模型分别经 `initDeshadowModel2` / `initDeshadowModelNew` 初始化并按会话释放。旧模型 CPU 数、fast mode、CPU affinity 默认分别为 `1 / false / false`（`restored-MagicFilterPreference.java.txt`）。
- `restored-ScannerPreferenceHelper.java.txt`：本地超级滤镜默认策略受实验参数 `ai_filter_default` 控制；本地优先对应值 `2`，默认超级滤镜可由 `>0` 开启，另有分离 IP 的本地配置覆盖值。
- `restored-SuperFilterGlobal.java.txt`：渠道/新用户资格也会限制超级滤镜显示/开放；并非只看本机是否有本地模型。

## 包内资源与原生库

对输入 APK 的 ZIP 成员名进行精确扩展名/关键词盘点：未发现 `.mnn`、`.onnx`、NCNN `.param/.bin` 模型文件或名称明显属于 super-filter/deblur 的权重文件。能看到 `libmagicenhancer.so`、`libimageprocessor.so`、`libMNN.so`、`libncnn.so` 等原生库；UI 图片和 loading 动画也在包内，但这些不是模型权重。

`libimageprocessor.so` 的已有静态导出/字符串证据包括 `ImageEnhance::InferNet`、`MNN::Interpreter::createFromFile/createFromBuffer`、`init_model`、`deblur_net`、`deblur_process` 与 JNI `ImageProcessor_initDeblur`。这证明 APK 含 MNN 推理基础设施和去模糊代码；它**不能**证明模型文件位于 APK、模型用于 `-12` 云端超级滤镜，或模型能够独立运行。模型可能通过其他资源/运行时下载提供，但本次证据未证实该来源。

## 已有原库实测

`restored-enhance-branches/recovered-enhance-branches-report.json` 记录了模拟器中对同一保留裁切图调用原始增强库的结果：

| 分支 | photo-1 / photo-2 状态 | 耗时 |
|---|---:|---:|
| old，mode 3，fast=false | 0 / 0 | 1509.7 / 1297.8 ms |
| old-fast，mode 3，fast=true | 0 / 0 | 903.0 / 903.7 ms |
| new，mode 3，threads=1 | 1 / 1 | 2223.7 / 2244.9 ms |

这些是原生库分支可执行性和返回值的受控证据；其中 mode 3 旧/新增强分支不是 `-12` 云端超级滤镜，也不代表原 App 的默认实验配置或端到端图像质量等价。

## 下一步（按信息增益排序）

1. 继续补齐原进度客户端 `ImageProgressClient.executeProgress` 的分支与结果码处理，确认 `-12` 失败时 UI/调用者具体选用哪种回退模式；目前只从 `enhanceImageAllS` 确认了失败后按传入的 `i4` 重试本地增强，但 `ImageProgressClient` 侧默认/传入值和失败 UI 尚未连起来。
2. 在研究模拟器上，通过原 App 的合法 UI 请求本地增强与 `-12` 各跑一次，记录网络可达/不可达时的返回码、输出文件 hash、请求/响应元数据。不能通过伪造服务端响应或改写返回值来推定真实服务器效果；如需观察明文 HTTP，先确认目标 SDK 的 TLS/抓包限制并使用应用拥有者可配置的测试代理。
3. 若能捕获模型下载/初始化日志，定点追踪 `ImageProcessor.initDeblur` 的实参、模型路径/文件 hash 和会话尺寸；随后只对解出的实际权重与网络结构做独立分析。当前缺少模型文件，因此不能提供本地 MNN 重放。
4. 若目标是小程序接入，可直接接入已恢复并实测的本地 `ImageSilverBulletFile`/增强库能力；`-12` 只有在服务授权、协议和服务端可用的前提下才能复现同一服务端效果，不能从 APK 静态代码推出可移植的算法实现。

## 证据边界

- 代码归因依据是 APK 中业务 DEX 恢复结果；文件见本目录 `restored-SuperFilterEngine.java.txt`、`restored-ScannerUtils.java.txt`、`restored-MagicEnhancer.java.txt`、`restored-SessionIdPoolManager.java.txt`、`restored-MagicFilterPreference.java.txt`、`restored-ScannerPreferenceHelper.java.txt`、`restored-SuperFilterGlobal.java.txt`。
- 原库运行报告为 `restored-enhance-branches/recovered-enhance-branches-report.json`，样图和分支对比见同目录。
- APK ZIP 成员扫描是对提供的 `B5739206C9BAE2AAAA68129F6D660A93.apk.1` 解包副本 `.work/camscanner/camscanner.apk` 的静态观察；本报告不覆盖服务端、账号权限、线上 A/B 配置或未触发的动态资源下载。
- REA 当前没有可用的 Windows ARM ELF 深度分析 provider：Ghidra 未配置且该集成不接受 ARM ELF；Hopper 不支持 Windows；IDA 未配置。因此这里使用的是已存在的 Ghidra/ELF 静态产物和 restored DEX，不把它表述为本轮 REA 原生函数伪代码证据。
